SQL Injection — Bypass de autenticación

La query de login concatena directamente los inputs del usuario. Esto permite modificar la lógica SQL e ingresar sin contraseña válida.

Formulario de login
Query que se ejecuta en la base de datos
SELECT * FROM users WHERE username='admin' AND password='wrong_password'
Payload inyectado: admin'--
El -- es un comentario en SQL. Todo lo que sigue queda ignorado, incluyendo la condición de contraseña. El sistema autentica sin verificarla.

Secretos expuestos — /debug

El endpoint /debug retorna todas las variables de entorno del servidor, incluyendo credenciales de base de datos y el secreto usado para firmar tokens JWT.

Paso 1 — Obtener los secretos

Un solo request expone todo.

Paso 2 — Forjar token de admin

Con el JWT_SECRET robado, el servidor puede crear un token firmado para cualquier usuario, incluyendo admin.

Token de admin forjado

Este token fue creado sin conocer la contraseña del admin. Usalo en el tab IDOR para acceder como admin.

GET /debug
Ejecutá GET /debug para ver las variables de entorno expuestas.
IDOR — Insecure Direct Object Reference

El endpoint /user/:id no valida si el token pertenece al usuario solicitado. Cualquier usuario autenticado puede ver los datos de cualquier otro.

Token de autenticación

Usá el token de carlos (login normal) para acceder a datos de admin.

Consultar usuario por ID
Acceso no autorizado. Estás viendo datos de un usuario distinto al que pertenece el token. El backend no valida la identidad.
GET /user/:id
Consultá un ID para ver los datos del usuario.
